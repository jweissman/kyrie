# Handoff: the state of Kyrie at the end of Mission 18

Written 4 November 2026 for an engineer starting Mission 19 who has not followed the work. It is a working document,
not a report: what the system is, how to run and test it, where things live, what is unfinished or fragile, and what
the builder believes keeps the game from feeling coherent. Line numbers are as of the commit that adds this file;
they drift, the file names do not.

Read alongside:

- [overview.md](../overview.md): the four layers, and one authored line followed to a remembered consequence. Start
  there for the architecture; this file adds what changed since and what is weak.
- [register.md](register.md): every finding of every review and author's report, one row each, with its status and
  evidence.
- [closure.md](closure.md): what Mission 18 set out to do and what it did (the phase-by-phase account below is the
  current one).
- [verification.md](../verification.md) and [performance.md](../performance.md): test tiers, CI, and costs.
- [doc/authoring/guide.md](../../authoring/guide.md): the Kyr language as authors use it; its examples are played by
  `test/authoring-guide.test.ts`.

## 1. What it is, in one paragraph

A browser RPG whose world is written in **Kyr**, a declarative language (places, passages, people, states, actions,
rules), run by **Kyrie**, a deterministic runtime (one world state, time in ten-minute watches, people with plans,
Orsino-derived combat), with worlds generated by **Deem** (a seeded generator library pinned in `package.json`). The
browser client (**the reader**, `web/reader`) has no rules of its own: every control is a legal command of the
runtime. A game is either an authored campaign (`data/campaigns/*.campaign.json`) or a generated country (a seed),
into which every authored adventure is placed as a province. Twenty-one adventures exist (`data/adventures/`), the
largest written by teams of agents with their own friction reports (`doc/adventures/*/`).

## 2. Setting up

```sh
bun install --frozen-lockfile        # Bun 1.4.3; Deem and the languages package come from git URLs pinned at commits
bun run web:build                    # writes site/ (the whole game in the page); rebuild after any .kyr or data change
bun x tsc --noEmit -p .              # typecheck (bun run typecheck also checks web/)
bin/kyrie help                       # the one CLI: play, lint, world, inspect, forecast, names, countries, …
```

The browser specs and the play server use Playwright's Chromium (`playwright-core`, a dev dependency). On the
builder's WSL host Chromium needed `libnss3` and `libnspr4` without root: `apt-get download libnss3 libnspr4`,
`dpkg-deb -x` each into `~/.cache/kyrie-nss/root`, then run with
`LD_LIBRARY_PATH=$HOME/.cache/kyrie-nss/root/usr/lib/x86_64-linux-gnu`. Browser specs are opt-in: `KYRIE_BROWSER=1`.

Machine care (the builder's WSL locked up repeatedly under load): one heavy job at a time (a full suite, a browser
run, a long lint), never two in parallel; worktrees and scratch under a directory that survives restarts (the builder
used `/var/tmp/kyrie`; `/tmp` is wiped).

## 3. Tests, gates and CI

| Tier | Command | What it runs | Time |
|---|---|---|---|
| quick | `bun run test:quick` | spec files that took under two seconds by `test/timings.json`, six workers; untimed files are left out and counted (`scripts/test-quick.ts`) | ~30 s, ~570 tests |
| changed | `bun run test:changed` | `bun test --changed=<since>` plus specs naming a changed data or fixture directory (`scripts/test-changed.ts`); a change under `data/catalog` or `data/rules` pulls in most of the suite | minutes to most of an hour |
| full | `bun test --parallel --timings=test/timings.json` | everything not opt-in | ~390 min serial; CI's job |
| browser | `KYRIE_BROWSER=1 bun test test/*-browser.test.ts` | 22 spec files in real Chromium against `site/` (rebuild first) | ~15 min |
| descents | `KYRIE_LONG=1 bun test test/descent.test.ts` | long autoplay descents | CI |

The builder's practice: typecheck, `eslint` on changed files, `test:quick`, the specs a change touches by name, then
commit; full, browser and descents on CI. `bun run test:timings` re-times every spec (needed when specs are added:
untimed files fall out of the quick tier and unbalance CI's shards).

CI (`.github/workflows/ci.yml`): lint and types; the suite in **five** shards balanced by `test/timings.json`
(45 minutes each while twenty of the Book of Faces' specs are balanced by estimated timings: re-time them); long
descents; browser specs. Pushing again cancels the run in progress (concurrency): a series of quick pushes leaves main
without a verdict, which happened for most of 3 November.

Regenerated artifacts a change can require, and the spec that catches a stale one:

- `web/bundles.generated.json`, the bundle index: `bun -e "import { AssetCatalog } from './src/cli/asset-catalog';
  await AssetCatalog.write(process.cwd());"` after any `.kyr` or data change (`test/repository*.test.ts`).
- The handbooks (`doc/handbook/`, `doc/architecture/capability-audit.md`): `bin/kyrie handbook` after catalog changes.
- The kept trace `test/fixtures/traces/wren-tower-climbed.transcript.json`: any change to generated worlds changes
  its digests; `bun scripts/redigest-trace.ts wren-tower-climbed` replays it and rewrites them, and must print "it
  comes where it came" (otherwise the change altered the play, not only the digests).
- `test/timings.json` when spec files are added.

ESLint is strict and owner-owned (`eslint.config.mts`, do not edit it): 120 columns, 55 lines a function, 380 lines a
file with comments skipped (tests 160 a function), no stray arrow functions assigned to variables. Four files sit
exactly at 380 counted lines (`src/lang/world.ts`, `src/ui/screen-model.ts`, `src/presentation/player-view.ts`,
`src/campaign/campaign.ts`) and three more within six: any addition there forces a split.

## 4. Architecture, and where things live

The four layers are as [overview.md](../overview.md) says. What a newcomer needs beyond it:

**A command's path.** The reader's `MenuModel` (`web/reader/menu-model.ts`) builds the page's choices from the
`Screen`; choosing one sends its command through `PlaySession` (`src/session/play-session.ts`) to `Campaign`
(`src/campaign/campaign.ts`), which resolves it against `PlayerView.choices` (`src/presentation/player-view.ts`),
applies it, and runs the watches it takes (`src/campaign/campaign-tick.ts`: people's plans, rules and events in
authored order, `Consequences` for items handed and spent, `FieldResolver` for `Resolve …` calls that touch creatures).
The new state is projected (`ScreenModel.build`, `src/ui/screen-model.ts`) and told (`Narrator`, `Glance`,
`DecisionFrame` in `src/presentation/`), and the reader draws it (`web/reader/stage/*`).

**Kyr.** Grammar `src/lang/Kyr.ohm`; parser `src/lang/module-parser.ts` (people in `person-parser.ts`, places and
passages lowered in `world-constructs.ts`); checks `src/lang/module-compiler.ts`; the world state and its queries
`src/lang/world.ts`. Shared rules every module is played by: `data/rules/*.kyr` (`core`, `passages`, `people`,
`care`, `belongings`, `discovery`, `dominion`, …; the list is `ModuleBundle.world` in
`src/campaign/module-bundle.ts`). Static grounding of actions: `src/campaign/action-schemas.ts`.

**Composition.** `ModuleBundle` loads a module's files, namespaces ids (`brood__webs`), joins imports and declares
catalog kinds a module names (`WorldConstructs.given`); `module-assembly.ts` adds the projected entities (members,
abilities, feats).

**Generated worlds.** `WorldAssembler` and `DrawnWorld` (`src/world/`) draw a country from a seed with Deem, then
**write Kyr as text** (`RegionWriter` and ~35 writers under `src/world/`) and load it like any module. Some content is
in data templates (`data/generation/**/*.kyrt`, filled by `KyrTemplates`, `src/world/kyr-template.ts`): the thirteen
works, the undertown, the wild's meetings. The rest is TypeScript (§8). Placed adventures are provinces
(`data/adventures/countries.json`, `src/world/provinces.ts`).

**The reader.** `web/reader/reader-app.tsx` holds the state; `stage/` the pages (the glance, the sheets Every way /
Look about / More, conversation, fight, the road); `map-view.tsx` and `board/` the world map (a flat SVG and a 3D
board); `plan-view.tsx` the plan below ground; `town-plan-view.tsx` the plan of a town, building or site above ground.

**Tools.** `bin/kyrie` (`src/cli/kyrie.ts`): `play`, `lint` (`kyr-lint.ts`, `campaign-lint.ts`, `author-lint.ts`),
`inspect` (why an act is not offered), `forecast` (each band against novices of each calling), `names` (surnames
taken), `countries --diff`, `handbook`, `reach`, `transcripts`, `prose`. Scripts worth knowing:
`scripts/play-server.ts` + `scripts/play-driver.py` (drive the built reader by labels and screenshot it),
`scripts/navigation-census.ts` (every place's ways as the page says them), `scripts/redigest-trace.ts`.

## 7. Known defects

Concrete, reproducible, not yet fixed:

- **Fights are noisy.** The reckoning plays six to twelve trial fights (`src/presentation/danger-sense.ts`) and its
  verdict wanders between neighbouring words for the same fight across seeds; one seeded fight can still go against
  its reckoning (a grave-robber reckoned "no match" killed a fresh warrior who missed every blow).
- **Lone novices die.** Balance by calling is unmeasured since October (PT-11, SYS-05): a lone mage or thief who
  stands still dies; the first-town jobs were retuned by hand on 3 November (great rats, the grave-robber's level).
- **Names.** The goings-on's people draw names from an unsexed table (`data/generation/tables/names.json`,
  `townsfolkName`): a woman can be "Rurik" (OWN-51).
- **Repetition.** A third of each country's narrated sentences appear word for word in most other countries (PT-15);
  two townsfolk of a trade could share a seen line until 3 November (fixed for seen and talk lines only).
- **Journeys and the road page.** Travel between hexes is the map's; a journey arrives whole unless something staged
  stops it. The road page is reached only then, and its browser spec was removed (NVR-23).
- **The aim the player follows lives in the browser.** `web/reader/followed.ts` keeps it in `localStorage` keyed by
  the protagonist's name and the country's, and stores the aim's *text*: a reworded objective drops the follow, and
  the engine does not know what the player is following (so the glance's step toward the aim can disagree: REV-08).
- **Presentation reads truth.** The screen model is built from the world state, not from what the company can know
  (a foe's hit points in the dark among it: ARV-H5).
- **Labels are rewritten by string replacement.** A masked name ("Known as") is put into labels by `replaceAll` of
  the real name (`PlayerView.unnamed`), and journeys undo it the same way (`Journey.masks`); a name that is a
  substring of another word would be replaced inside it.
- **What sleep is.** `Meanwhile asleep(actor)` exists, but the shared camp and rest do not use it, so a rule at
  midnight fires during an ordinary camp (LUL-02).

## 8. Fragile and provisional: what the builder regards as a stopgap

From a read-only survey of the code at handoff; each is a design debt, not a bug, until it becomes one.

**Generated Kyr written as strings.** About 35 files under `src/world/` build Kyr source with template literals and
`JSON.stringify` for quoting; none goes through `src/lang/module-writer.ts` (only `world-audit.ts` and
`compose/ledger.ts` do). Escaping differs between paths (`KyrTemplates.fill` escapes braces; `JSON.stringify` does
not, and `{id}` references rely on that). Moved to data templates: the works (`data/generation/works/*.kyrt`, read by a
second dialect in `src/world/history/work-plans.ts`), the undertown (still part TypeScript in
`src/world/region-undertown.ts`: its notice, read action and catacombs), the wild's meetings. Not moved, largest first:
`community/community-writer.ts` (whole NPC speeches), `deep/deep-sites.ts`, `settlement-writer.ts`,
`region-zones.ts`, `region-traffic.ts`, `deep/deep-rivals.ts`, `region-fellows.ts`, `deep/deep-mechanisms.ts`,
`region-market.ts`, `deep/deep-rooms.ts`, `region-roads.ts`, and smaller ones. `RegionWriter.files` splits the output
by counting braces outside quotes and hoists `Kind`/`Species` lines by regex; the manifest's export list rebuilds ids
(`${s.id}_green`, `_taproom`, `_innkeeper`) by naming convention apart from the writers that emit them.

**Meaning read from id shapes.** Module prefixes (`/^([a-z0-9]+)__/`, `split('__')`) decide a line's installation, a
going-on's topic (`src/presentation/own-words.ts`), a skill check's subject. `region__` and id shapes identify places:
`src/ui/itinerary.ts` recognises march-stones and provinces only by `/__edge_…$/` and `region__gate_…` (its comment
calls this "the only handle on them today"); stretches of the wild are `/__t\d+$/` (`src/ui/land-model.ts`), and that
alone decides which exits get a compass bearing (`src/ui/headings.ts`) and so which are the map's
(`MenuModel.stays`). Passage kinds are compared as stripped strings (`.replace(/^.*way_/, '')`). Event logs are parsed
as strings (`src/presentation/visited-places.ts`, `spoken.ts`, `narration.ts`).

**The reader re-parses English.** The panorama (`web/reader/stage/panorama.tsx`) parses sentences the world writes
("To the north, some way off: …", "You know it by its look") back into structure; an aim is matched to a place by a
name regex in the aim's text (`web/reader/aims.ts`); services classify needs by item-name regex (`src/ui/services.ts`);
the reader finds a person's talk by `/#talk$/` on choice ids.

**Hardcoded content in TypeScript.** Prices and item ids (`settlement-writer.ts`: rations, torch and candle at one
coin; `region-market.ts`: fourteen techniques, twelve `fine_*` blades, thirteen spells, a fallback price of 40),
animals and their pronouns (`community/community.ts`), scene prose (`region-roads.ts` fords and bridges,
`region-zones.ts`, `deep/*`), the page's darkness text (`player-view.ts`).

**Special-case navigation.** "A drawn country" is `!!screen.region?.land?.tracts` (`MenuModel.inside`), and much of
the reader branches on it: travel and compass steps are hidden only there; authored countries keep their authors'
walks. Below ground shows `PlanView`; above ground `TownPlan` (which excludes underground rooms, and draws a site as a
town). Sites are found by the `${id}_site` suffix and towns by `${destination}_green`. `TownPlan` places colliding or
gridless rooms by a nearest-free-cell heuristic; generated towns' grids collide often.

**Heuristic aims and leads.** The glance's leads come from a hand-tuned tier table (`src/ui/promotion.ts`, three at
most, two ways, one "own"); aims are ordered by `Stakes.here` (names this place, then "own" by an `origin__` id or a
kin predicate, then the rest); the reader's default follow is the first aim, kept once taken. Objectives are prose
strings with no identity.

**Quest logic in templates.** The undertown's three jobs keep per-town relations (`{t}_u_given`, `_done`, `_paid`)
and a three-stage objective ladder; each group in `undertown.kyrt` has one option, so every town has all three
troubles; `region-undertown.ts` turns the option's name into the foe's id. The expedition contract
(`src/world/expedition-contract.ts`) is an audit, run by `test/world-audit.test.ts`, not a runtime structure.

**Process-global state.** String-keyed static caches with crude bounds (`DangerSense.reckoned` cleared past 200,
`ModuleBundle.parses` past 400, `WorldGrid.draws` unbounded, `ItemCatalog.uses`, `Histories.plans`), ~40 WeakMap
memos keyed by module or entity arrays, and `LocalCatalog.install`, which writes a module's kinds into the global
`Canon` and `ItemCatalog` and must be undone by `reset()`. One process runs one world at a time comfortably; two at
once (a test that starts two campaigns) can see each other's kinds (COR-04, ARV-H7).

**Stopgaps the builder added in the last two days**, each with a reason recorded at its site:

- the no-break space joining a `Known as` with a comma, so the page's name/role split at ", " does not find it
  (`PersonParser.PersonKnown`);
- `Journey.masks`, so authors' steps naming a masked person still match;
- `OwnWords`: a going-on's topic hides the shared question of it while offered, by module prefix;
- the danger reckoning's "play every trial" (slower, still noisy);
- CI's 45-minute suite limit while timings are estimated;
- `test/known-as-labels.test.ts` and `test/two-modules-one-town.test.ts`: these judge "another module" by id prefix.

## 9. Partly implemented features

- **The decision frame.** After an act: done (`src/presentation/decision-frame.ts`, `test/decision-frame.test.ts`).
  Before an act (now, aim, acts, inspect, reference): not begun (REV-05, SYS-01, IND-04).
- **Plans.** Below ground, levels; above ground, towns, buildings of three rooms or more, sites. No stairs or levels
  stacked, no vertical convention (NVR-20, NVR-21); generated towns' grids collide.
- **The wild.** Meetings by land and hour, leading to sites; no turns of route, camp, weather or supplies (REV-03).
- **Successors and renewal.** The debt and the kin's errand point on; each trouble seen through renews the country;
  herbs and the kits end where they end (PT-01).
- **Revelations and notes.** A revelation brought to light by an act is set apart; one seen on arriving is not
  (NAR-14). Notes say their source; never measured over long play (NAR-12).
- **Portable places** (the circus's pitches): designed and not built (WPC-01, with the reason in the register).
- **Interior plans and the map** are first drafts the owner asked to iterate on screenshots.

## 10. Outstanding migrations

In the order the builder would take them:

1. **Content generators into data templates** (AUT-25, ARV-H4, ARV-M3, ARV-M6): the writers in §8, largest first, onto
   `KyrTemplates` or `ModuleWriter`, with one escaping rule. The undertown and the works show the pattern.
2. **Declared facts instead of id shapes** (ARV-L2, ARV-M4): a place's kind, a stretch, a march-stone, a province, a
   module's ownership as facts the generators assert, read by `itinerary.ts`, `headings.ts`, `land-model.ts`,
   `own-words.ts`.
3. **Objectives with identity**, and the followed aim in the engine (REV-08): an objective id, so the reader can keep a
   follow by id and the glance can lead toward it.
4. **Per-campaign catalogs and caches** (COR-04, ARV-H7), with an owner and a reset for each static cache.
5. **States scoped to their thing** (AUT-07, IFR-10): today state names share the module namespace.
6. **Presentation from what the company knows** (ARV-H5).
7. **One save format** (ARV-A24).

## 11. Design assumptions that have caused trouble

- **One namespace for a world's names.** Every adventure's surnames, states and kinds share one space; adding an
  adventure means renaming clashes (Book of Faces vs Quittance on 3 November) and the names spec catches it late.
- **Ids carry meaning** (§8): convenient for generators, brittle for everything that reads them.
- **Generated content as text.** Writing Kyr as strings made the generators fast to write and slow to change; every
  content fix is a TypeScript change and a world-wide digest change.
- **Prose objectives.** An aim is its sentence; ordering, following and matching aims to places all work on text.
- **A drawn country versus an authored one.** Navigation, travel and the map branch on it throughout the reader;
  authored countries keep walks the owner wants gone from drawn ones.
- **Fights resolved to the death by default.** Authored fights wait on a band's fall, so morale cannot be the default
  without touching them (REV-16).
- **Simulation as judgement.** The danger reckoning and the forecast simulate fights; they are honest on average and
  noisy per fight, and they cost time per page.
- **The quick suite is chosen by recorded time.** Specs not in `test/timings.json` silently leave it; journeys by
  label break when wording changes (the journey matcher treats steps as regular expressions, so "East" matches
  "North-east").

## 12. What keeps the game from feeling coherent, in the builder's order

1. **Between the town and the site there is no game.** Travel is the map's alone and arrives whole; the wild's meetings
   are the only turns, sparse and small. Nothing asks a decision of route, camp, supplies or weather, so the loop is
   town, then a jump, then a site (REV-03, REV-17, OWN-78).
2. **The engine does not know what the player is doing.** Aims are prose, the followed one is in the browser, leads
   come from a tier table: the page can lead somewhere other than where the player means to go (REV-08, REV-05).
3. **Every page is still a menu.** A glance of three leads, plates, three sheets and a map: coherent now, but a list of
   verbs, not a scene with a decision in it. The frame before an act is the missing piece (REV-05, IND-04, OWN-77).
4. **Depth is uneven.** The first town's three jobs have causes, keys and consequences; most of the country's
   goings-on and works are one fight or one exchange deep (OWN-75), and the generated prose repeats across countries
   (PT-15).
5. **Fights are trivial or lethal for a lone novice,** and the reckoning that should make that legible is noisy
   (PT-11, SYS-05).
6. **Navigation inside places.** Generated towns had thirty-odd ways in one list; the plan helps, the list remains, and
   authored places have twin ways the census counts (OWN-81, LOR-05).
7. **The world is not legible as one world.** Provinces, planes and countries are placed and told of, but a player
   meets them as separate books (NAV-10, B2, B3).

What the builder would do first in Mission 19: objectives with identity and the followed aim in the engine (2), then
one vertical slice (the first town, one road, one site and the return) designed and tuned end to end before anything
is generalised. [handoff-supplement.md](handoff-supplement.md) gives the reasoning, the reference journey, and why
structure alone would not make the loop satisfying.

## 13. Practices and pitfalls

- Never `git stash` in this repository: the owner keeps uncommitted work in the tree. Use a worktree for a baseline.
- Stage explicit paths; the owner's untracked files sit in `doc/`.
- No edits in a tree while its suite runs; CI and long runs read the tree as it is.
- A label change breaks journeys (steps are regular expressions over labels); grep `test/fixtures/*/` and `test/*.ts`
  for the old wording first.
- Adding an adventure: merge in a worktree, run `bin/kyrie names` on its surnames, lint its tests (adventures arrive
  with eslint errors in their specs), add its friction to the register, time its specs.
- When CI is red, read each shard's log (`gh run view --job <id> --log`, available only once the whole run completes)
  before pushing again: another push cancels the run.
