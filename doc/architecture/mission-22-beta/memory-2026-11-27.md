# What a world start holds

27 November 2026. The platform builder. Measured before anything was changed. The instrument is `scripts/performance/world-memory.ts` (with
`world-memory-peel.ts`), run through `scripts/machine/heavy.sh` on the lead's WSL machine, warm parse store, one
process per reading, `--world s0 --as human/warrior/Wenna` unless said:

```
scripts/machine/heavy.sh bun scripts/performance/world-memory.ts --no-frame            # the start, peeled
scripts/machine/heavy.sh bun scripts/performance/world-memory.ts --no-frame --heap     # and each install's heap
scripts/machine/heavy.sh bun scripts/performance/world-memory.ts --no-frame --hold 're' # those ids left out
```

How it reads the heap: after a turn of the event loop, collected and swept (`gcAndSweep`, then `heapStats`). Read
without the turn, an async function's just-finished frame keeps the whole life alive (56 MB that seemed unfreeable).
The heap is then taken apart by **peeling**: each part of the life let go in turn, then each process cache emptied in
turn, the heap collected after each. Each is charged what it alone kept of what was left; what two share is charged
to the later. The order is in the script.

Machine load moves the times by 30 to 50 per cent between runs (another builder held a heavy slot). Each comparison
below is between runs made back to back.

## The headline

| | eager start (today) | the first country's stories held back |
|---|---|---|
| start, PlayTool.start to a session | 5.1 to 5.5 s | 3.1 to 3.3 s |
| of which composing the world | 3.8 to 4.0 s | 1.7 s |
| installs | 40, 1.8 s of loading | 12, 0.7 to 0.8 s |
| creatures generated | 604 | 239 |
| heap kept after the start | 198 MB | 136 MB |
| peak resident set (`/usr/bin/time -v`) | 619 to 630 MB | 457 MB |

The heap kept is about a third of the peak. The rest is garbage made on the way: parses, clones (`structuredClone`
of kept parses and compiled modules), JSON, Deem's matches. A cold parse store (after any change to the files the store
is keyed by) took 13.6 s, with 158 parses for 4.9 s of matching, and peaked at 790 MB resident.

**The single finding that matters most: provinces are already installed lazily.** `Frontier.province` installs a
province of the first country when a company first stands at its way in (Mission 18's Gate B), and `Frontier.expand`
installs a country beyond a march when one first stands at its march-stone. An s0 start installs none of the 41
provinces. What it installs whole is the first country's own stories: 15 modules of 13 library placements (the
circus, the walk, the keep, the howe, the arcology, the factors, the fellowship, the brood and its sink, the den, the
tower, the drover and his oxen, the players, the disputation) and the 13 word modules that spread news of them. Every
one of these lies four to seventeen hexes from where the life begins (the start is region__s1_approach; the nearest
placement, the disputation and the fellowship's hall, four hexes off). Under unity of place none can be reached until a
way out is earned.

The right column is those 28 modules left out of the manifest (`--hold`): their absence, measured, the upper bound of
what installing them lazily saves at a start. **Two seconds of the start (40 per cent), 62 MB of the heap it keeps (31
per cent) and 165 MB of its peak (26 per cent).**

A province, when it is first reached, costs 0.9 to 2.0 s and 4 to 20 MB (the Long Man 0.9 s and 3.7 MB; Wrayford 2.0 s
and 19.9 MB; each includes the road on into it and a projection of everyone's facts, which grows with the world). The
41 together, installed eagerly, would cost about a minute and some 400 MB: their laziness is essential, and is already
there. What it lacks is preparation: the first arrival waits that second or two (the design's preparation step).

## What the heap holds

After an s0 start, no frame told, the life peeled first and then the process's caches (MB):

| what | MB | what it is |
|---|---|---|
| the code, module records and JSON imported | 46.5 | before anything runs |
| the catalogs read (the canon's vocabulary, creation's catalog) | 3.7 | |
| creation's setting (the origins, rolled) | about 8 | read before the phases (a separate probe) |
| **the life** | | |
| campaign.compiled, the joined module | 33.4 | region 3.1 MB of JSON, rules and kinds 3.0, circus 1.8, walk 0.56, keep 0.39, howe 0.38, arcology 0.36, every other under 0.13 |
| campaign.committed, the world as committed | 11.9 | facts and their indexes |
| campaign.current, the state | 4.9 | |
| campaign.definition, the vocabulary, the creatures, the rest | 2.0 | |
| **the process's caches** | | |
| CompiledModules, modules compiled before | 33.7 | keyed by each module's whole text joined: the key strings hold every source again |
| Deem.parsed, Deem's matches | 21.6 | in the deem package: every expression's ohm MatchResult kept whole, its matcher's memo table with it |
| ParseCache, Kyr parses in the process | 16.1 | keyed by text (12 MB of keys allowed) |
| ModuleBundle.parses and rulesets | 1.3 | shared with ParseCache's values |
| WorldDrawings, ModuleCanon, DeclarationParses, KeptPredicates and the rest | 2.5 | |
| left once all is let go | 66 to 68 | the code, the catalogs and creation's setting (58), and about 10 no cache here names |

A heap snapshot (`Bun.generateHeapSnapshot()`, dominators computed over it) of what stays once the life is let go
says the same by shape: 42 to 46 MB of strings held by maps (the cache keys above), 23 MB of kept parse and compile
variants, 11 MB of ohm MatchResults (Deem's), 10 MB of code.

**With the first frame told, the life is not let go.** The frame adds 25 MB (the grounding's kept schemas, 4 MB; the
frame's kept parts) and, once session, journey and runner are dropped, the heap does not fall: 50 to 55 MB more stays
than without the frame, though the snapshot holds no Campaign and no PlaySession. Something the frame reaches keeps
the life's module, world and operators by an edge the snapshot does not show (a map's bucket). This matters for specs
that start several worlds in one worker (3 to 4 GB each): OR-1740.

## The largest consumers, and what each would save

1. **The first country's stories, installed though out of reach: 62 MB kept, 165 MB of peak, 2.0 s.** Measured by
   holding them back. Lazy installation (lazy-provinces.md) takes this, with OR-418 as its precondition (done here).
2. **CompiledModules' and the parse caches' keys: about 40 MB of strings.** A key is the module's whole text (or a
   file's). Keyed by a hash of the text (TextHash, already used for the rules' edition), with the text compared on a
   hit, they would hold one copy. Within src/campaign (CompiledModules) and src/lang (ParseCache): OR-1742.
3. **Deem's kept matches: 21.6 MB at a start, 16 MB of it the stories'.** Kept whole by text so that templates read
   again are not parsed again; kept as the CST only, or with the matcher's memo table dropped, they would hold a
   fraction. In the deem package, outside the engine: OR-1741.
4. **The joined module and the world, 45 MB, half of it the stories'.** Falls with (1).
5. **Clones.** structuredClone is 0.9 s of two starts. Kept parses are cloned on every read (ModuleBundle.parsed: the
   shared rules' files are read once per install, so each install clones every rule file it is joined to), and on
   every write (ParseCache.set, CompiledModules.set). A compiled module read back is already shared (CompiledModules.get
   with `shared`, AX-04, test/frozen-modules: the kept values frozen, a world begun and played from them, nothing
   written). Sharing on read is safe wherever the reader writes nothing, and the frozen-modules spec proves it: the
   rule sources read for each install (`ruleSources` in ModuleBundle.loading, read by the vocabulary's verb binding,
   which writes nothing) are the next. Clone on write is needed where the caller changes what it was given after
   keeping it (CompiledModules.set: the module compiled is then sized and given the canon's entities); there, the
   owned copy loading already makes for the kept path (`ModuleBundle.owned`, which copies only the arrays it changes)
   would replace the whole clone. Both cut garbage, and so peak, more than the heap kept: OR-1744.
